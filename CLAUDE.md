# FPL Agent — working notes

A Fantasy Premier League squad optimiser: public FPL API in, expected-points
model, ILP squad selection, r/FantasyPL sentiment. Read `README.md` for what
the tool does and how the maths works. This file is the operational context a
fresh session needs.

## Running it

```bash
pip install -e ".[dev]"          # `pulp` matters: without it the ILP degrades to local search
fpl-agent build --horizon 6 --no-reddit
fpl-agent team <entry-id> --horizon 6 --no-reddit
python -m pytest -q
```

The console script is `fpl-agent` and the package is `fpl_agent`. Anything
still saying `fpl-builder` or `fpl_builder` is stale — the project was renamed
from "TestProject"/"FPL Team Builder", and the GitHub repo is now `FPL-Agent`.

## Things that will waste your time if you don't know them

**Reddit 403s from anywhere that isn't a residential IP.** Verified on a
GitHub-hosted runner. Every cloud session — Codespaces, web Claude Code —
hits this. Pass `--no-reddit` unless `REDDIT_CLIENT_ID` and
`REDDIT_CLIENT_SECRET` are set. The FPL API itself is fine from cloud IPs;
that was tested separately and all endpoints returned 200.

**`tests/test_api.py::test_expired_cache_refetches` fails on Windows only,
intermittently.** Coarse NTFS mtime resolution against `cache_ttl=0`, in the
`>` comparison in `FPLClient._read_cache`. It passes 139/139 on Linux. It is
a real bug in the expiry check but not a regression — don't go hunting for
what you broke.

**Pre-season, the API is a different shape.** Before GW1 kicks off:
`minutes`/`starts` hold last season's totals, `form` is 0.0 for everyone,
`strength_attack_*`/`strength_defence_*` are zeroed in favour of a 1-5
`strength_overall_*` tier, and `entry/{id}/event/{gw}/picks/` 404s until the
deadline passes. `analysis.py` and `models.py` compensate for each of these;
see the "Running it before the season starts" section of the README before
assuming a pre-season number is a bug.

**`finished` is not "the match was played".** The API leaves `finished`
False for a day or more after the whistle while bonus and match data are
confirmed; `finished_provisional` is the flag that flips at full time. Counting
only `finished` made every team read as having played zero games for the first
days of each gameweek, which sent `start_probability` down its pre-season branch
and inverted the ranking -- nailed-on starters at ~3%, players yet to feature at
~58%. Use `Fixture.played`, never `Fixture.finished`, for anything that counts
games played or looks ahead.

**`defensive_contribution` counts defensive ACTIONS, not awards won.** League
median is ~7.7 per 90, season high 515. An award needs 10 actions in a match
for a defender and 12 for everyone else. This bit once already.

## Scoring rules

The model targets the **2026/27** rules. The reference is a Google Doc,
"Architectural Blueprint for an Autonomous Fantasy Premier League AI Agent":
<https://docs.google.com/document/d/16krzm2KcpoEguO6hCdkaiKGFsPGGsTUxLUhxg4zeSJE/edit>

`--no-2627-bps` scores against the old BPS instead. This is not a cosmetic
switch: the old system picks a 4-4-2 and the new one a 3-5-2, because
defenders now need three CBI per BPS point instead of two.

The BPS multipliers in `analysis.py` (`BPS_2627_ADJUSTMENT`,
`PENALTY_TAKER_BPS_ADJUSTMENT`) are a judgment-call translation of published
rule text into numbers. Nobody has real 2026/27 data yet. Treat them as
assumptions to revisit once gameweeks land, not as measured values.

## Conventions

- Default branch is `main`. Branch for changes; don't commit straight to it.
- Run the suite before pushing. 139 tests, and they need no network — the
  fixtures under `tests/fixtures/` are generated by
  `scripts/generate_sample_data.py` and mirror the real API schema. If you
  change what a field *means*, fix the generator and regenerate, or the tests
  will happily confirm the wrong thing.
- Projections are estimates, not predictions. Minutes are the largest error
  source and the model cannot know a team sheet. Say so in any output that a
  human will act on.
